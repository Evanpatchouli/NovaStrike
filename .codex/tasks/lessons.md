# Lessons Learned

## 2026-06-01 GSI 能力边界

1. 在 `playing` 视角下，GSI 的全局字段（如 `allgrenades`）并不稳定可用，设计功能时要先确认数据上限。
2. 当数据源无法提供高置信事件时，优先下线易误导功能，而不是继续堆叠推断逻辑。
3. 调试能力应保留最小闭环：最近 payload 查询接口 + 可视化调试面板。

## 2026-06-01 配置管理

1. Steam Library 路径采用显式配置比自动猜测更稳健。
2. cfg 同步采用“内容比对后写入”可减少无意义覆盖。
3. 启动自检 + 手动同步双入口有助于降低排障成本。

## 2026-06-01 风险提示设计

1. 状态提醒要先分级再文案化：先确定风险等级（safe/warning/danger），再给出可执行建议，避免“只有告警没有动作”。
2. 购买建议与购买风险应拆分：一个回答“该怎么买”，一个回答“这样买的后果是什么”，可解释性更强。
3. Overlay 中高频信息宜采用“badge + 标签”组合，阅读成本低于长文本堆叠。
